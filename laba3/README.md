# Лабораторна №3 — Поведінка в часі, ефекти та анімація

Завдання: https://volodymyr-kovdrysh.github.io/frontend-labs-2026/labs/lab03/index.html

## Походження та структура

Продовження компонентної моделі світлофора з `laba2`: React, Vite, компоненти `TrafficLights` і `Light`, CSS-перехід. Додано відсутні передумови CP2: ручний вибір, StatsBar, лічильники та керовану орієнтацію.

За вимогою власника репозиторію результат збережений окремо у `laba3`, щоб не змінювати здані лабораторні. Це організаційний відступ від інструкції викладача продовжувати роботу в тому самому каталозі. Новий Vite-шаблон не генерувався: використана конфігурація попередньої роботи.

## Запуск

Потрібен Node.js, сумісний із Vite 8 (перевірено на Node 24.21.0).

```sh
cd ~/my-frontend-labs/laba3
npm ci
npm run dev
```

Перевірки: `npm run build`, `npm run lint`.

## Поведінка

- Початково ручний режим, червоний сигнал, нульові лічильники.
- Кожне натискання лампи, включно з повторним вибором активної, збільшує лише її ручний лічильник.
- Запуск продовжує з поточної фази: red → yellow → green → yellow → red.
- Ручний жовтий відповідає індексу 1, тому наступним буде зелений.
- У автоматичному режимі лампи вимкнені для ручного вибору; таймер не змінює статистику.
- Зупинка зберігає фазу, статистику й орієнтацію. Відновлення починає повний відлік поточної фази.
- Орієнтація змінює лише розташування того самого компонента.
- Додаткова можливість: вибір тривалості 0,5 / 1,5 / 3 с; зміна очищає старий інтервал і починає новий відлік.

## Для захисту

1. **Власник стану — App.** Він зберігає `phaseIndex`, `isAutomatic`, `direction`, `intervalMs` і `counts`. Видимий колір обчислюється через `cycle[phaseIndex]`, окремого стану кольору немає.
2. **Чому чотири фази?** Жовтий повторюється з різними наступними кольорами. Індекси 1 та 3 розрізняють ці ситуації.
3. **Подія та ефект.** Кнопки змінюють `isAutomatic`; лампа через callback змінює фазу і лічильник. Ефект синхронізує стан режиму з зовнішнім API таймерів.
4. **Налаштування ефекту.** Якщо `isAutomatic` істинний, створюється один `setInterval`.
5. **Cleanup.** `clearInterval(timerId)` скасовує саме цей інтервал перед зміною залежностей або демонтуванням. Тому повторні запуски не накопичують таймери.
6. **Залежності `[isAutomatic, intervalMs]`.** Визначають необхідність і частоту таймера. `cycle` — константа модуля; setter React стабільний; попередня фаза приходить у функціональне оновлення, тож читати її із замикання не потрібно.
7. **Функціональне оновлення.** `setPhaseIndex(previous => (previous + 1) % cycle.length)` працює з актуальним значенням без пересоздання інтервалу після кожної фази.
8. **StrictMode залишений.** Додаткове налаштування/очищення у розробці перевіряє симетричність ефекту.
9. **Анімація.** CSS-клас `active` походить від стану. Transition змінює opacity, transform і box-shadow; без CSS логіка циклу збережеться.
10. **StatsBar — похідний інтерфейс.** Загальна кількість обчислюється із трьох лічильників, окремого стану суми немає.

## Проведені перевірки

- Production-збірка та lint вихідних файлів — успішні.
- У браузері: ручний зелений збільшив тільки зелений лічильник.
- Зміна на горизонтальну орієнтацію зберегла фазу й статистику.
- Зафіксовані два повні цикли з інтервалом 1,5 с: 1 → 2 → 3 → 4 → 1 → 2 → 3 → 4 → 1.
- Автоматичні кроки не збільшили ручні лічильники.
- П'ять швидких запусків/зупинок: після очікування понад тривалість фази сигнал не змінився.
- Після зупинки ручний жовтий обрав фазу 2 та збільшив лише жовтий лічильник.

## Показ викладачу

Обрати кілька ламп → показати статистику → змінити орієнтацію → запустити два цикли → зупинити → почекати → вручну обрати жовтий → показати useEffect і cleanup у `src/App.jsx`.
