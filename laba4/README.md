# Лабораторна №4 — Маршрутизація та спільний стан

Завдання: https://volodymyr-kovdrysh.github.io/frontend-labs-2026/labs/lab04/index.html

## Запуск

```sh
nvm use 24
cd ~/my-frontend-labs/laba4
npm ci
npm run dev
```

Перевірки: `npm run build`, `npm run lint`, `npm audit`.

## Виконані вимоги

- React Router: BrowserRouter, Routes, Route, NavLink, Link та Outlet.
- Маршрути `/`, `/traffic-light`, `/stats`, `*` і додатковий `/status` лише для читання.
- Один спільний AppLayout з навігацією та позначенням активного маршруту.
- Один TrafficLightsProvider над App/Routes, що володіє фазою, режимом, орієнтацією, тривалістю, лічильниками, діями та ефектом таймера.
- Поточний колір похідний від phaseIndex; загальна кількість натискань похідна від counts.
- TrafficLightPage читає Context і передає props компонентам Light/TrafficLights/StatsBar.
- StatsPage читає ті самі дані без власних копій стану; показує три лічильники, суму, фазу, режим, орієнтацію й тривалість.
- StatusPage демонструє додаткового споживача того самого Context.
- HomePage та NotFoundPage не володіють станом світлофора.
- Ручний вибір, статистика, орієнтація, запуск/зупинка та CSS-переходи ЛР3 збережені.
- Автоматичний цикл: red → yellow → green → yellow → red; ручний жовтий завжди вибирає фазу 2.
- useEffect створює лише один інтервал при isAutomatic=true. Cleanup clearInterval виконується перед зміною залежностей і демонтуванням.
- Залежності ефекту: isAutomatic та intervalMs. Функціональний setter отримує актуальну попередню фазу без зайвого перезапуску інтервалу.
- StrictMode залишено. Даних сервера, авторизації чи localStorage немає.

## Структура

```text
main.jsx: StrictMode → BrowserRouter → TrafficLightsProvider → App
App: Routes → AppLayout → Outlet
                            ├ HomePage
                            ├ TrafficLightPage
                            ├ StatsPage
                            ├ StatusPage
                            └ NotFoundPage
```

Компоненти Light, TrafficLights, StatsBar і StateSummary працюють через props та не імпортують Router або Context.

## Пояснення реалізації

**SPA:** один HTML-документ; Router змінює URL і дочірні компоненти без повного завантаження документа. NavLink/Link забезпечують внутрішню SPA-навігацію, NavLink також позначає активну сторінку. Outlet показує відповідний дочірній маршрут у спільному макеті.

**Чому Context тепер потрібен:** у попередній роботі стан обслуговував один екран і передавався через props. Тепер світлофор і статистика — різні гілки маршрутів. Їм потрібен спільний власник вище обох сторінок.

**Context не замінює useState:** провайдер зберігає дані через useState, синхронізує таймер через useEffect, а Context лише доставляє дані та дії сторінкам.

**Чому стан не скидається:** провайдер не демонтується при зміні маршруту. Якщо поставити його всередині TrafficLightPage, вихід зі сторінки знищить стан і таймер. Таймер живе у провайдері, тому працює також на статистиці, головній і сторінці стану.

**Межі відповідальності:** Context містить лише дані світлофора. Автентифікація та серверний обмін не належать цій предметній області. Компоненти представлення залишаються незалежними від навігації та повторно використовуються.

**Навігація та перезавантаження:** переходи через Link зберігають пам'ять провайдера. Повне оновлення вкладки або прямий перехід із завантаженням нового документа створюють новий застосунок із початковим станом — це відповідає CP4.

## Перевірка в браузері

1. Головна відкрилася зі спільною навігацією.
2. На світлофорі виконано зелений і двічі жовтий: counts = {red:0, yellow:2, green:1}, total=3.
3. Після вибору горизонтальної орієнтації й переходу на stats показані ті самі значення, жовтий і фаза 2.
4. Увімкнено автоматичний режим; на stats зафіксовано повний цикл: фази 2 → 3 → 4 → 1 → 2 із кроком 1,5 с. Лічильники не змінилися.
5. На status збережені автоматичний режим, горизонтальна орієнтація та total=3.
6. Після повернення на світлофор і зупинки, переходу через головну на stats та очікування понад 1,5 с сигнал не змінився.
7. Прямий запит невідомої адреси показав контрольовану сторінку 404 зі спільною навігацією.
8. Production build та lint успішні; npm install повідомив 0 вразливостей.

## Організація репозиторію

`laba4` продовжує код і конфігурацію `laba3`; новий Vite-шаблон не генерувався. Окремий каталог збережено за домовленістю з власником репозиторію для розділення лабораторних. Це організаційний відступ від вказівки викладача працювати в тому самому каталозі. Попередні лабораторні залишаються незмінними.

Виробниче розгортання поза обсягом ЛР4. Для BrowserRouter на хостингу потрібен fallback вкладених адрес на index.html; dev-сервер Vite це вже забезпечує. Стан між перезавантаженнями не зберігається за вимогами CP4.
